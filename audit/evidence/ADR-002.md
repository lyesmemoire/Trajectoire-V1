# Architecture Decision Record (ADR)
**ID**: ADR-002
**Title**: Intégration stricte des Timeouts LLM via AbortSignal (COR-003)
**Date**: 2026-07-30
**Status**: Accepted

## 1. Context
Les appels LLM dans `InterviewService` s'appuient sur `RetryManager` mais ne transmettent aucun signal d'annulation (`AbortSignal`) au client sous-jacent (`OpenAIProvider`). Par conséquent, lorsqu'une réservation de crédit expire (ou que le client coupe la connexion WS), la requête réseau vers OpenAI continue en arrière-plan (zombie request), consommant des crédits fournisseur et risquant de committer la transaction après le timeout. Ceci viole les invariants métier de facturation (RSK-003).

## 2. Decision
Nous allons propager un objet `AbortSignal` de haut en bas :
1. `ChatCompletionParams` acceptera un `signal?: AbortSignal`.
2. `OpenAIProvider` injectera ce signal dans sa requête HTTP `client.chat.completions.create({..., options: { signal }})` (supporté par le SDK OpenAI Node.js).
3. `InterviewService` acceptera un signal dans `InterviewInput` et `InterviewContext` et le propagera via `RetryManager`.
4. `RetryManager` passera une fonction usine au lieu d'une fonction sans paramètres, ou plus simplement, le scope de fermeture (closure) qui englobe le signal abort fonctionnera naturellement si le signal est passé explicitement au moment de l'appel final.

## 3. Alternatives Considered
- *Timeout global par Promise.race* : Rejeté car cela ne coupe pas la socket réseau sous-jacente avec le fournisseur IA (OpenAI), entraînant des fuites de requêtes.

## 4. Consequences
- Les délais (timeouts) appliqués par le `ConversationService` couperont instantanément la requête OpenAI, libérant le port et annulant la transaction sans risque de commit tardif.
- Fiabilisation du contrat transactionnel Reserve -> Commit/Rollback.

## 5. Rollback Plan
Le changement de signature est rétro-compatible grâce au paramètre optionnel (`signal?: AbortSignal`). En cas d'erreur de compatibilité TypeScript, l'attribut peut être retiré du provider.
