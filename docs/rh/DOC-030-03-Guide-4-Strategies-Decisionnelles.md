## 1. Objectif

Définir le guide des 4 stratégies décisionnelles sous incertitude pour MVP-030 Uncertainty Management Engine. Ce guide structure la gestion décisionnelle de l'incertitude avec 4 stratégies distinctes : réduire l'incertitude avant décision, décider sous incertitude assumée, reporter la décision, et escalader la décision.

---

## 2. Principe Fondateur

Face à l'incertitude, le moteur propose une stratégie décisionnelle adaptée. Chaque stratégie est appliquée selon des critères précis (enjeu, réductibilité de l'incertitude, temps disponible) et propose des actions spécifiques pour gérer l'incertitude de manière responsable et transparente.

---

## 3. Stratégie 1 — Réduire l'Incertitude avant Décision

### 3.1 Quand Appliquer

**Critères :**
- L'enjeu est élevé (poste senior, impact business significatif)
- L'incertitude est réductible (information manquante obtainable)
- Le temps le permet (délai de recrutement suffisant)

**Exemples :**
- Recrutement d'un C-Level
- Poste avec impact stratégique
- Candidat avec potentiel élevé mais informations incomplètes

---

### 3.2 Actions Proposées

**Questions spécifiques à poser en entretien :**
- Questions ciblées sur les zones d'incertitude identifiées
- Questions comportementales pour valider les hypothèses
- Questions de mise en situation pour tester les compétences

**Documents supplémentaires à demander :**
- Références spécifiques (anciens managers, collègues)
- Portfolio ou réalisations détaillées
- Tests de compétences techniques
- Évaluations psychométriques

**Références à prendre :**
- Références professionnelles
- Références académiques
- Références personnelles (si pertinent)

**Tests à faire passer :**
- Tests de compétences techniques
- Tests de soft skills
- Tests de personnalité
- Tests de raisonnement

**Second entretien avec focus défini :**
- Focus sur les zones d'incertitude
- Entretien avec un autre évaluateur
- Entretien avec le futur manager

---

### 3.3 Exemple de Mise en Œuvre

```
STRATÉGIE 1 — Réduire l'incertitude avant décision

Enjeu : Recrutement d'un CTO pour une scale-up
Incertitude : Capacité à construire une équipe technique

Actions proposées :
  1. Second entretien avec focus sur l'expérience de management d'équipe
  2. Références spécifiques : 2 anciens collaborateurs directs
  3. Test de leadership et de management
  4. Exercice de mise en situation : construction d'une équipe fictive
  5. Entretien avec le CEO pour évaluer l'alignement stratégique

Délai estimé : 2 semaines
Objectif : Réduire l'incertitude de niveau 3 à niveau 1
```

## 4. Stratégie 2 — Décider sous Incertitude Assumée

### 4.1 Quand Appliquer

**Critères :**
- L'incertitude est irréductible (fondamentale ou temporaire non résolvable)
- L'enjeu est modéré (poste non critique, impact limité)
- Le temps presse (délai de recrutement court)

**Exemples :**
- Recrutement d'un poste junior
- Candidat avec profil atypique mais potentiel
- Situation d'urgence opérationnelle

---

### 4.2 Ce que le Moteur Fait

**Documenter l'incertitude résiduelle :**
- Liste des zones d'incertitude
- Niveau de confiance pour chaque zone
- Sources de l'incertitude

**Identifier le scénario le plus probable :**
- Basé sur les données disponibles
- Probabilité estimée
- Hypothèses sous-jacentes

**Identifier le pire scénario et sa probabilité :**
- Description du pire scénario
- Probabilité estimée
- Impact potentiel

**Proposer des mesures de mitigation :**
- Si le pire scénario se réalise
- Actions préventives
- Plans de contingence

---

### 4.3 Exemple de Mise en Œuvre

```
STRATÉGIE 2 — Décider sous incertitude assumée

Enjeu : Recrutement d'un développeur junior
Incertitude : Évolution des compétences techniques dans 2 ans

Incertitude résiduelle documentée :
  - Niveau de confiance : 2 (modéré)
  - Source : Complexité humaine + évolution du marché
  - Hypothèse : Le candidat continue d'apprendre

Scénario le plus probable (probabilité 70%) :
  Le candidat se développe normalement et atteint le niveau senior en 2 ans

Pire scénario (probabilité 30%) :
  Le candidat stagne à son niveau actuel et ne progresse pas

Mesures de mitigation si le pire scénario se réalise :
  - Plan de formation structuré dès l'arrivée
  - Mentorat par un développeur senior
  - Évaluation à 6 mois avec possibilité de réorientation
  - Budget de formation alloué

Recommandation : Recruter sous incertitude assumée avec mesures de mitigation
```

## 5. Stratégie 3 — Reporter la Décision

### 5.1 Quand Appliquer

**Critères :**
- L'incertitude est trop élevée (niveau 3 ou 4 sur plusieurs points)
- L'enjeu est critique (poste senior, impact stratégique)
- L'information manquante est obtainable (délai raisonnable)

**Exemples :**
- Recrutement d'un C-Level avec informations incomplètes
- Candidat avec profil exceptionnel mais zones d'ombre importantes
- Situation où une décision précipitée serait risquée

---

### 5.2 Ce que le Moteur Dit

**Format :**
```
Je recommande de ne pas décider maintenant.
L'incertitude sur [point X] est trop élevée pour un poste de ce niveau.
Voici comment obtenir l'information manquante dans [délai] : [actions]
```

---

### 5.3 Exemple de Mise en Œuvre

```
STRATÉGIE 3 — Reporter la décision

Enjeu : Recrutement d'un VP Sales pour une scale-up
Incertitude : Capacité à construire une équipe commerciale de 20 personnes

Recommandation :
  Je recommande de ne pas décider maintenant.
  L'incertitude sur la capacité à construire une équipe commerciale de 20 personnes
  est trop élevée pour un poste de ce niveau.

Comment obtenir l'information manquante dans 3 semaines :
  1. Second entretien avec focus sur l'expérience de scaling d'équipe
  2. Références spécifiques : 3 anciens managers directs
  3. Exercice de mise en situation : plan de recrutement pour 20 personnes
  4. Entretien avec le CEO pour évaluer l'alignement culturel

Délai : 3 semaines
Objectif : Réduire l'incertitude de niveau 4 à niveau 1
```

## 6. Stratégie 4 — Escalader la Décision

### 6.1 Quand Appliquer

**Critères :**
- L'incertitude est systémique (dépasse le périmètre RH)
- La décision dépasse le niveau HR (enjeux stratégiques)
- Des enjeux stratégiques sont en jeu (impact sur l'entreprise)

**Exemples :**
- Recrutement d'un C-Level avec implications stratégiques majeures
- Décision qui affecte la direction de l'entreprise
- Situation où des facteurs externes ou politiques sont en jeu

---

### 6.2 Ce que le Moteur Dit

**Format :**
```
Cette décision doit être prise à un niveau supérieur.
L'incertitude porte sur [point stratégique] qui dépasse le périmètre RH.
Je recommande d'impliquer : [qui]
```

---

### 6.3 Exemple de Mise en Œuvre

```
STRATÉGIE 4 — Escalader la décision

Enjeu : Recrutement d'un CEO pour une startup
Incertitude : Alignement avec la vision stratégique des investisseurs

Recommandation :
  Cette décision doit être prise à un niveau supérieur.
  L'incertitude porte sur l'alignement avec la vision stratégique des investisseurs
  qui dépasse le périmètre RH.

Je recommande d'impliquer :
  - Le Board of Directors
  - Les investisseurs principaux
  - Le fondateur (si applicable)
  - Un consultant externe spécialisé en gouvernance

Processus recommandé :
  1. Présentation de la cartographie d'incertitude au Board
  2. Discussion stratégique avec les investisseurs
  3. Validation de la vision alignée
  4. Décision collégiale
```

## 8. Algorithme de Sélection de Stratégie

### 8.1 Processus Global

```typescript
async function selectDecisionStrategy(evaluation: Evaluation, uncertaintyMap: UncertaintyMap): Promise<DecisionStrategy> {
  // 1. Évaluation des critères
  const criteria = await evaluateCriteria(evaluation, uncertaintyMap);
  
  // 2. Sélection de la stratégie
  let strategyType: 'reduce' | 'assume' | 'defer' | 'escalate';
  
  if (criteria.stakeLevel === 'critical' && criteria.uncertaintyReducibility === 'reducible' && criteria.timeAvailable === 'sufficient') {
    strategyType = 'reduce';
  } else if (criteria.uncertaintyReducibility === 'irreducible' && criteria.stakeLevel === 'moderate' && criteria.timeAvailable === 'limited') {
    strategyType = 'assume';
  } else if (criteria.stakeLevel === 'critical' && criteria.uncertaintyReducibility === 'partially_reducible' && criteria.timeAvailable === 'sufficient') {
    strategyType = 'defer';
  } else if (criteria.stakeLevel === 'critical' && criteria.uncertaintyReducibility === 'irreducible' && criteria.uncertaintyIsSystemic) {
    strategyType = 'escalate';
  } else {
    // Par défaut : réduire si possible, sinon assumer
    strategyType = criteria.uncertaintyReducibility === 'reducible' ? 'reduce' : 'assume';
  }
  
  // 3. Construction de la stratégie
  const strategy: DecisionStrategy = {
    strategyId: generateStrategyId(),
    strategyType,
    evaluatedAt: new Date(),
    criteria,
    actions: await generateActions(strategyType, evaluation, uncertaintyMap),
    metadata: {
      createdBy: 'MVP-030 Uncertainty Management Engine',
      context: evaluation.context,
      version: '1.0'
    }
  };
  
  // 4. Ajout des éléments spécifiques selon la stratégie
  if (strategyType === 'assume') {
    strategy.uncertaintyDocumentation = await documentUncertainty(uncertaintyMap);
  } else if (strategyType === 'defer') {
    strategy.deferralPlan = await createDeferralPlan(evaluation, uncertaintyMap);
  } else if (strategyType === 'escalate') {
    strategy.escalationPlan = await createEscalationPlan(evaluation, uncertaintyMap);
  }
  
  return strategy;
}
```

## 9. Stockage et Gestion

### 9.1 Schéma SQL

```sql
CREATE TABLE decision_strategy (
  id VARCHAR(36) PRIMARY KEY,
  strategy_type VARCHAR(50) NOT NULL CHECK (strategy_type IN ('reduce', 'assume', 'defer', 'escalate')),
  evaluated_at TIMESTAMP NOT NULL,
  
  criteria JSON NOT NULL,
  actions JSON NOT NULL,
  uncertainty_documentation JSON,
  deferral_plan JSON,
  escalation_plan JSON,
  metadata JSON NOT NULL,
  
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

CREATE INDEX idx_decision_strategy_type ON decision_strategy(strategy_type);
CREATE INDEX idx_decision_strategy_date ON decision_strategy(evaluated_at);
```
