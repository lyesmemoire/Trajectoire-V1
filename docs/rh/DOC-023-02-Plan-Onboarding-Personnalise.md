# DOC-023-02 : Plan d'Onboarding Personnalisé

**Version:** 1.0  
**Date:** 2026-08-03  
**Statut:** Draft  
**Auteur:** Trajectoire Team

---

## 1. Objectif

Définir le système de génération de plan d'onboarding personnalisé pour MVP-023 Onboarding Intelligence Engine. Ce système génère automatiquement un plan d'onboarding personnalisé à partir du profil du candidat retenu, couvrant 4 phases (Semaine 1 Découverte, Mois 1 Installation, Mois 3 Confirmation, Mois 6 Autonomie) avec priorités d'intégration, objectifs, livrables, points de feedback, et bilans structurés.

---

## 2. Principe Fondateur

Le plan d'onboarding est généré automatiquement à partir du profil du candidat retenu. Il couvre 4 phases : Semaine 1 Découverte (priorités d'intégration basées sur les forces et zones de développement, personnes clés à rencontrer, documents à maîtriser, points de vigilance pour le manager), Mois 1 Installation (objectifs de fin de mois, premiers livrables, points de feedback planifiés, signaux de succès et d'alerte), Mois 3 Confirmation (bilan à 90 jours, évaluation de l'adéquation réelle, ajustement du plan, décision de confirmation de période d'essai), Mois 6 Autonomie (bilan à 6 mois, comparaison avec les prédictions du moteur MVP-021, axes de développement pour l'année 1).

---

## 3. Semaine 1 — Découverte

### 3.1 Priorités d'Intégration

**Principe :**
Les priorités d'intégration sont basées sur les forces du candidat et ses zones de développement identifiées lors du processus de recrutement.

**Forces du candidat :**
- Compétences techniques fortes
- Soft skills développés
- Expérience pertinente
- Motivation intrinsèque

**Zones de développement :**
- Compétences à renforcer
- Soft skills à développer
- Connaissances à acquérir
- Processus à maîtriser

**Exemples de priorités :**
- Si le candidat a une forte capacité d'apprentissage → prioriser la formation technique
- Si le candidat a des soft skills relationnels forts → prioriser l'intégration sociale
- Si le candidat a une zone de développement sur les processus → prioriser la maîtrise des processus

---

### 3.2 Personnes Clés à Rencontrer

**Principe :**
Identification des personnes clés à rencontrer en priorité pour une intégration réussie.

**Catégories de personnes clés :**
- Manager direct
- Équipe immédiate
- Stakeholders clés
- Mentors ou buddies
- RH / Support

**Priorisation :**
- Haute priorité : manager direct, équipe immédiate
- Moyenne priorité : stakeholders clés, mentors
- Basse priorité : RH / support (sauf cas spécifiques)

---

### 3.3 Documents et Processus à Maîtriser

**Principe :**
Identification des documents et processus à maîtriser en priorité.

**Documents prioritaires :**
- Description du poste
- Objectifs et KPIs
- Processus métier
- Outils et logiciels
- Politiques de l'entreprise

**Priorisation :**
- Haute priorité : description du poste, objectifs et KPIs
- Moyenne priorité : processus métier, outils et logiciels
- Basse priorité : politiques de l'entreprise

---

### 3.4 Points de Vigilance pour le Manager

**Principe :**
Identification des points de vigilance pour le manager basés sur le profil du candidat.

**Exemples de points de vigilance :**
- Si le candidat a une zone de développement sur l'autonomie → supervision renforcée initiale
- Si le candidat a une forte créativité → canaliser vers les objectifs
- Si le candidat a une préférence pour le travail individuel → encourager la collaboration

---

## 4. Mois 1 — Installation

### 4.1 Objectifs de Fin de Mois

**Principe :**
Définition des objectifs de fin de mois mesurables et réalistes.

**Types d'objectifs :**
- Objectifs d'intégration (compréhension du poste, de l'équipe, de l'entreprise)
- Objectifs techniques (maîtrise des outils, des processus)
- Objectifs de performance (premiers livrables, contribution aux projets)

**Critères de qualité :**
- Spécifiques (SMART)
- Mesurables
- Atteignables
- Pertinents
- Temporels

---

### 4.2 Premiers Livrables Attendus

**Principe :**
Définition des premiers livrables attendus pour le premier mois.

**Types de livrables :**
- Livrables d'apprentissage (formation, certification)
- Livrables techniques (documentation, code, rapports)
- Livrables de projet (contribution aux projets en cours)

**Critères de qualité :**
- Clairs et définis
- Avec critères d'acceptation
- Avec deadline
- Avec responsable

---

### 4.3 Points de Feedback Planifiés

**Principe :**
Planification des points de feedback formels et informels.

**Types de feedback :**
- Feedback formel (réunion structurée, grille d'évaluation)
- Feedback informel (échanges informels, check-in)

**Fréquence :**
- Semaine 1 : feedback informel quotidien
- Semaine 2 : feedback formel hebdomadaire
- Semaine 3-4 : feedback formel hebdomadaire

---

### 4.4 Signaux de Succès à Surveiller

**Principe :**
Identification des signaux de succès à surveiller pendant le premier mois.

**Signaux de succès :**
- Intégration sociale rapide (relations avec l'équipe)
- Compréhension rapide du poste et des attentes
- Atteinte des premiers objectifs
- Feedbacks positifs du manager et de l'équipe
- Engagement et motivation

---

### 4.5 Signaux d'Alerte à Surveiller

**Principe :**
Identification des signaux d'alerte à surveiller pendant le premier mois.

**Signaux d'alerte :**
- Absentéisme les premières semaines
- Feedbacks négatifs du manager
- Isolement dans l'équipe
- Non-atteinte des premiers objectifs
- Questionnements sur le poste ou l'entreprise

---

## 5. Mois 3 — Confirmation

### 5.1 Bilan à 90 Jours Structuré

**Principe :**
Génération d'un bilan structuré à 90 jours pour évaluer l'intégration.

**Structure du bilan :**
- Revue des objectifs du premier mois
- Évaluation de la performance
- Évaluation de l'intégration sociale
- Évaluation de l'adéquation avec le poste
- Feedback du candidat

---

### 5.2 Évaluation de l'Adéquation Réelle

**Principe :**
Évaluation de l'adéquation réelle entre le candidat et le poste.

**Critères d'évaluation :**
- Compétences techniques
- Soft skills
- Motivation
- Intégration culturelle
- Performance

**Comparaison avec les prédictions :**
- Comparaison avec les prédictions du moteur MVP-021
- Identification des écarts
- Analyse des causes des écarts

---

### 5.3 Ajustement du Plan si Nécessaire

**Principe :**
Ajustement du plan d'onboarding si nécessaire basé sur le bilan à 90 jours.

**Types d'ajustements :**
- Renforcement des formations
- Ajustement des objectifs
- Modification du style de management
- Changement des responsabilités

---

### 5.4 Décision de Confirmation de Période d'Essai

**Principe :**
Recommandation de décision de confirmation de période d'essai.

**Options de décision :**
- Confirmer : le candidat atteint les objectifs et s'intègre bien
- Étendre : le candidat a besoin de plus de temps (avec justification)
- Terminer : le candidat n'atteint pas les objectifs (avec justification)

---

```typescript
async function generatePersonalizedOnboardingPlan(candidateId: string, jobId: string): Promise<PersonalizedOnboardingPlan> {
  // 1. Récupération des données du candidat
  const candidate = await getCandidate(candidateId);
  const job = await getJob(jobId);
  
  // 2. Identification des forces et zones de développement
  const strengths = await identifyStrengths(candidate);
  const developmentZones = await identifyDevelopmentZones(candidate);
  
  // 3. Génération du plan Semaine 1
  const week1Discovery = await generateWeek1Discovery(candidate, job, strengths, developmentZones);
  
  // 4. Génération du plan Mois 1
  const month1Installation = await generateMonth1Installation(candidate, job);
  
  // 5. Génération du plan Mois 3
  const month3Confirmation = await generateMonth3Confirmation(candidate, job);
  
  // 6. Génération du plan Mois 6
  const month6Autonomy = await generateMonth6Autonomy(candidate, job);
  
  // 7. Construction du plan
  const plan: PersonalizedOnboardingPlan = {
    planId: generatePlanId(),
    candidateId,
    jobId,
    generatedAt: new Date(),
    
    week1Discovery,
    month1Installation,
    month3Confirmation,
    month6Autonomy
  };
  
  // 8. Sauvegarde du plan
  await savePersonalizedOnboardingPlan(plan);
  
  return plan;
}
```

### 7.2 Génération du Plan Semaine 1

```typescript
async function generateWeek1Discovery(
  candidate: Candidate,
  job: Job,
  strengths: string[],
  developmentZones: string[]
): Promise<Week1Discovery> {
  // Génération des priorités d'intégration
  const integrationPriorities = await generateIntegrationPriorities(strengths, developmentZones);
  
  // Identification des personnes clés à rencontrer
  const keyPeopleToMeet = await identifyKeyPeopleToMeet(job);
  
  // Identification des documents à maîtriser
  const documentsToMaster = await identifyDocumentsToMaster(job);
  
  // Génération des points de vigilance pour le manager
  const managerWatchPoints = await generateManagerWatchPoints(candidate, developmentZones);
  
  return {
    integrationPriorities,
    keyPeopleToMeet,
    documentsToMaster,
    managerWatchPoints
  };
}

async function generateIntegrationPriorities(strengths: string[], developmentZones: string[]): Promise<{
  priority: string;
  description: string;
  basedOn: 'strength' | 'development_zone';
}[]> {
  const priorities: {
    priority: string;
    description: string;
    basedOn: 'strength' | 'development_zone';
  }[] = [];
  
  // Priorités basées sur les forces
  for (const strength of strengths) {
    priorities.push({
      priority: `Capitaliser sur ${strength}`,
      description: `Utiliser votre force en ${strength} pour contribuer rapidement`,
      basedOn: 'strength'
    });
  }
  
  // Priorités basées sur les zones de développement
  for (const zone of developmentZones) {
    priorities.push({
      priority: `Renforcer ${zone}`,
      description: `Se concentrer sur le développement de ${zone} avec un accompagnement adapté`,
      basedOn: 'development_zone'
    });
  }
  
  return priorities;
}
```

## 9. Stockage et Gestion

### 9.1 Schéma SQL

```sql
CREATE TABLE personalized_onboarding_plan (
  id VARCHAR(36) PRIMARY KEY,
  candidate_id VARCHAR(36) NOT NULL,
  job_id VARCHAR(36) NOT NULL,
  generated_at TIMESTAMP NOT NULL,
  
  week1_discovery JSON NOT NULL,
  month1_installation JSON NOT NULL,
  month3_confirmation JSON NOT NULL,
  month6_autonomy JSON NOT NULL,
  
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  
  FOREIGN KEY (candidate_id) REFERENCES candidates(id),
  FOREIGN KEY (job_id) REFERENCES jobs(id)
);

CREATE INDEX idx_personalized_onboarding_plan_candidate ON personalized_onboarding_plan(candidate_id);
CREATE INDEX idx_personalized_onboarding_plan_job ON personalized_onboarding_plan(job_id);
CREATE INDEX idx_personalized_onboarding_plan_date ON personalized_onboarding_plan(generated_at);
```
