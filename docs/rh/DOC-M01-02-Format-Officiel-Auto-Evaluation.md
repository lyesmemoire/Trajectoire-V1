# DOC-M01-02 : Format Officiel de l'Auto-Évaluation

**Version:** 1.0  
**Date:** 2026-08-04  
**Statut:** Draft  
**Auteur:** Trajectoire Team

---

## 1. Objectif

Définir le format officiel de l'auto-évaluation produit par le moteur avant le debrief final. Ce document structure le format de sortie obligatoire qui synthétise l'auto-évaluation du moteur sur les 8 dimensions.

---

## 2. Principe Fondateur

Le format officiel de l'auto-évaluation est produit avant le debrief final. Il permet au recruteur de comprendre la qualité de l'évaluation effectuée par le moteur, d'identifier les limites de l'évaluation, et de prendre des décisions éclairées sur la suite du processus.

---

## 3. Format de Sortie Obligatoire

### 3.1 Structure Générale

```
┌──────────────────────────────────────┐
│ AUTO-ÉVALUATION DU MOTEUR           │
│ Entretien : [Candidat] / [Poste]    │
│ Date      : [Date]                  │
├──────────────────────────────────────┤
│ QUALITÉ GLOBALE DE CET ENTRETIEN   │
│ Score : X/10                        │
│                                     │
│ CE QUE J'AI BIEN FAIT :            │
│ → [élément 1 avec preuve]          │
│ → [élément 2 avec preuve]          │
│ → [élément 3 avec preuve]          │
│                                     │
│ CE QUE J'AURAIS DÛ FAIRE           │
│ DIFFÉREMMENT :                      │
│ → [action manquée 1]               │
│   Impact : [élevé/modéré/faible]   │
│ → [action manquée 2]               │
│   Impact : [élevé/modéré/faible]   │
│                                     │
│ ZONES INSUFFISAMMENT ÉVALUÉES :    │
│ → [zone 1] — Raison : [explication]│
│ → [zone 2] — Raison : [explication]│
│                                     │
│ BIAIS POTENTIELS DÉTECTÉS :        │
│ → [biais 1] — Risque : [niveau]    │
│ → [biais 2] — Risque : [niveau]    │
│                                     │
│ FIABILITÉ DE MON ÉVALUATION :      │
│ Globale    : Élevée/Modérée/Faible │
│ Par zone   :                        │
│   Compétences : [niveau]            │
│   Soft skills : [niveau]            │
│   Culture fit : [niveau]            │
│   Motivation  : [niveau]            │
│                                     │
│ RECOMMANDATION :                    │
│ [Action pour améliorer l'évaluation]│
│ Exemple : "Second entretien sur X" │
└──────────────────────────────────────┘
```

### 3.2 Moment de Production

**Déclenchement :**
- Après chaque entretien
- Avant de produire le debrief final
- Analyse systématique des 8 dimensions

## 4. Sections Détaillées

### 4.1 En-tête

**Contenu :**
- AUTO-ÉVALUATION DU MOTEUR
- Entretien : [Candidat] / [Poste]
- Date : [Date]

**Exemple :**
```
AUTO-ÉVALUATION DU MOTEUR
Entretien : Sophie Dupont / DRH
Date : 2026-08-04
```

### 4.2 Qualité Globale de Cet Entretien

**Contenu :**
- Score global : X/10
- Calculé à partir des 8 dimensions

**Échelle de scoring :**
- 9-10 : Excellent
- 7-8 : Bon
- 5-6 : Acceptable
- 3-4 : À améliorer
- 0-2 : Insuffisant

**Exemple :**
```
QUALITÉ GLOBALE DE CET ENTRETIEN
Score : 7.5/10
```

### 4.3 Ce Que J'ai Bien Fait

**Contenu :**
- Liste des éléments réussis avec preuves
- Maximum 3 éléments principaux

**Format :**
→ [élément] avec preuve : [preuve concrète]

**Exemple :**
```
CE QUE J'AI BIEN FAIT :
→ Couverture des zones critiques avec preuve : J'ai exploré 4/5 zones critiques en profondeur
→ Creusage des réponses vagues avec preuve : J'ai creusé 4/5 réponses vagues et obtenu des preuves concrètes
→ Détection des réponses préparées avec preuve : J'ai appliqué les techniques de démasquage sur 3 signaux de préparation
```

### 4.4 Ce Que J'aurais Dû Faire Différemment

**Contenu :**
- Liste des actions manquées
- Impact de chaque action : élevé / modéré / faible

**Format :**
→ [action manquée]
  Impact : [élevé/modéré/faible]

**Exemple :**
```
CE QUE J'AURAIS DÛ FAIRE DIFFÉREMMENT :
→ Creuser davantage sur la zone "Budget RH"
  Impact : modéré
→ Poser la question sur la stratégie de l'entreprise
  Impact : élevé
```

### 4.5 Zones Insuffisamment Évaluées

**Contenu :**
- Liste des zones insuffisamment évaluées
- Raison pour chaque zone

**Format :**
→ [zone] — Raison : [explication]

**Exemple :**
```
ZONES INSUFFISAMMENT ÉVALUÉES :
→ Budget RH — Raison : Temps manquant en fin d'entretien
→ Stratégie de l'entreprise — Raison : Fil conversationnel dévié vers le management
```

### 4.6 Biais Potentiels Détectés

**Contenu :**
- Liste des biais potentiels détectés
- Niveau de risque pour chaque biais : élevé / modéré / faible

**Format :**
→ [biais] — Risque : [niveau]

**Exemple :**
```
BIAIS POTENTIELS DÉTECTÉS :
→ Biais de halo — Risque : modéré (force initiale en communication a pu masquer lacunes en management)
→ Biais de confirmation — Risque : faible (impression initiale positive confirmée par questions orientées)
```

### 4.7 Fiabilité de Mon Évaluation

**Contenu :**
- Fiabilité globale : Élevée / Modérée / Faible
- Fiabilité par zone :
  - Compétences : [niveau]
  - Soft skills : [niveau]
  - Culture fit : [niveau]
  - Motivation : [niveau]

**Échelle de fiabilité :**
- Élevée : Preuves suffisantes, cohérence interne, absence de biais majeurs
- Modérée : Preuves limitées, quelques incohérences mineures, biais potentiels
- Faible : Preuves insuffisantes, incohérences significatives, biais majeurs

**Exemple :**
```
FIABILITÉ DE MON ÉVALUATION :
Globale    : Modérée
Par zone   :
  Compétences : Élevée
  Soft skills : Modérée
  Culture fit : Modérée
  Motivation  : Faible
```

### 4.8 Recommandation

**Contenu :**
- Action pour améliorer l'évaluation
- Exemple : "Second entretien sur X"

**Types de recommandations :**
- Second entretien sur les zones manquantes
- Approfondissement sur une dimension spécifique
- Validation par un DRH humain
- Revoir le scoring avec ajustements

**Exemple :**
```
RECOMMANDATION :
Second entretien sur le Budget RH et la Stratégie de l'entreprise pour améliorer la fiabilité de l'évaluation
```

## 6. Structure de Données (TypeScript)

```typescript
interface SelfEvaluationOutput {
  evaluationId: string;
  interviewId: string;
  candidateId: string;
  positionId: string;
  
  header: {
    title: string;
    candidate: string;
    position: string;
    date: Date;
  };
  
  globalQuality: {
    score: number;
    scale: 'excellent' | 'good' | 'acceptable' | 'toImprove' | 'insufficient';
  };
  
  whatWentWell: {
    element: string;
    proof: string;
  }[];
  
  whatCouldBeImproved: {
    missedAction: string;
    impact: 'high' | 'moderate' | 'low';
  }[];
  
  insufficientlyEvaluatedZones: {
    zone: string;
    reason: string;
  }[];
  
  detectedBiases: {
    bias: string;
    risk: 'high' | 'moderate' | 'low';
    explanation?: string;
  }[];
  
  reliability: {
    global: 'high' | 'moderate' | 'low';
    byZone: {
      competences: 'high' | 'moderate' | 'low';
      softSkills: 'high' | 'moderate' | 'low';
      cultureFit: 'high' | 'moderate' | 'low';
      motivation: 'high' | 'moderate' | 'low';
    };
  };
  
  recommendation: {
    action: string;
    type: 'secondInterview' | 'deepening' | 'humanValidation' | 'scoringReview';
  };
  
  metadata: {
    version: string;
    createdAt: Date;
    lastUpdated: Date;
  };
}
```

## 7. Stockage et Gestion

### 7.1 Schéma SQL

```sql
CREATE TABLE self_evaluation_output (
  id VARCHAR(36) PRIMARY KEY,
  interview_id VARCHAR(36) NOT NULL,
  candidate_id VARCHAR(36) NOT NULL,
  position_id VARCHAR(36) NOT NULL,
  
  header JSON NOT NULL,
  global_quality JSON NOT NULL,
  what_went_well JSON NOT NULL,
  what_could_be_improved JSON NOT NULL,
  insufficiently_evaluated_zones JSON NOT NULL,
  detected_biases JSON NOT NULL,
  reliability JSON NOT NULL,
  recommendation JSON NOT NULL,
  metadata JSON NOT NULL,
  
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
);

CREATE INDEX idx_self_evaluation_output_interview ON self_evaluation_output(interview_id);
CREATE INDEX idx_self_evaluation_output_candidate ON self_evaluation_output(candidate_id);
CREATE INDEX idx_self_evaluation_output_position ON self_evaluation_output(position_id);
```

## 10. Conclusion

Le format officiel de l'auto-évaluation structure la sortie obligatoire produite par le moteur avant le debrief final. Structure : En-tête (AUTO-ÉVALUATION DU MOTEUR, Entretien, Date), Qualité globale (Score X/10), Ce que j'ai bien fait (éléments réussis avec preuves), Ce que j'aurais dû faire différemment (actions manquées avec impact), Zones insuffisamment évaluées (zones avec raisons), Biais potentiels détectés (biais avec niveau de risque), Fiabilité de mon évaluation (globale et par zone), Recommandation (action pour améliorer l'évaluation). Exemple complet pour un entretien DRH. Structure de données TypeScript, stockage SQL, API endpoints pour la gestion.

- Produit avant le debrief final

- Score global sur 10
- Éléments réussis avec preuves
- Actions manquées avec impact
- Zones insuffisamment évaluées
- Biais potentiels détectés
- Fiabilité globale et par zone
- Recommandation d'action
- Exemple complet
