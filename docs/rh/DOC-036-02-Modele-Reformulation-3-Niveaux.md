## 1. Objectif

Définir le modèle de reformulation pour MVP-036 Active Listening Engine. Ce modèle structure les 3 niveaux de reformulation que le moteur utilise avant de poser la question suivante pour montrer que chaque mot a été entendu, distinguant un entretien d'un interrogatoire.

---

## 2. Principe Fondateur

Avant de poser la question suivante, le moteur reformule ce qui vient d'être dit. La reformulation montre que le moteur a vraiment écouté et compris, pas simplement attendu que le candidat finisse. Les 3 niveaux de reformulation permettent de s'adapter à la complexité et à l'importance de la réponse.

---

## 3. Niveau 1 — Reformulation Simple

### 3.1 Objectif

Vérifier la compréhension de base de la réponse du candidat.

### 3.2 Structure

**Template :**
```
Si je vous comprends bien,
vous avez [résumé en 1 phrase].
C'est bien cela ?
```

### 3.3 Exemples

**Exemple 1 :**
- Candidat : "J'ai travaillé sur un projet de refonte du site web pendant 6 mois."
- Reformulation : "Si je vous comprends bien, vous avez travaillé sur un projet de refonte du site web pendant 6 mois. C'est bien cela ?"

**Exemple 2 :**
- Candidat : "J'ai quitté mon précédent poste parce que je cherchais de nouveaux défis."
- Reformulation : "Si je vous comprends bien, vous avez quitté votre précédent poste parce que vous cherchiez de nouveaux défis. C'est bien cela ?"

**Exemple 3 :**
- Candidat : "Je suis très motivé par ce poste car il correspond à mes compétences."
- Reformulation : "Si je vous comprends bien, vous êtes très motivé par ce poste car il correspond à vos compétences. C'est bien cela ?"

### 3.4 Quand Utiliser

- Réponses courtes et simples
- Vérification rapide de compréhension
- Transitions rapides
- Questions de clarification mineures

---

## 4. Niveau 2 — Reformulation Enrichie

### 4.1 Objectif

Vérifier la compréhension détaillée de la réponse du candidat en incluant le contexte, l'action, et le résultat.

### 4.2 Structure

**Template :**
```
Ce que vous décrivez,
c'est une situation où [contexte]
et vous avez choisi de [action].
Le résultat a été [résultat].
C'est bien ce que vous avez vécu ?
```

### 4.3 Exemples

**Exemple 1 :**
- Candidat : "J'ai travaillé sur un projet de refonte du site web pendant 6 mois. L'équipe était de 5 personnes. Nous avons utilisé React et Node.js. Le résultat a été une augmentation de 30% du trafic."
- Reformulation : "Ce que vous décrivez, c'est une situation où vous avez travaillé sur un projet de refonte du site web avec une équipe de 5 personnes, et vous avez choisi d'utiliser React et Node.js. Le résultat a été une augmentation de 30% du trafic. C'est bien ce que vous avez vécu ?"

**Exemple 2 :**
- Candidat : "J'ai quitté mon précédent poste parce que je cherchais de nouveaux défis. L'entreprise était stable mais il n'y avait pas d'opportunités d'évolution. J'ai trouvé un poste plus stimulant."
- Reformulation : "Ce que vous décrivez, c'est une situation où votre précédente entreprise était stable mais sans opportunités d'évolution, et vous avez choisi de quitter pour chercher de nouveaux défis. Le résultat a été un poste plus stimulant. C'est bien ce que vous avez vécu ?"

**Exemple 3 :**
- Candidat : "Je suis très motivé par ce poste car il correspond à mes compétences. J'ai de l'expérience en développement web et en gestion de projet. Je veux évoluer vers un rôle plus stratégique."
- Reformulation : "Ce que vous décrivez, c'est une situation où vous avez de l'expérience en développement web et en gestion de projet, et vous avez choisi de postuler pour ce poste qui correspond à vos compétences. Le résultat est que vous voulez évoluer vers un rôle plus stratégique. C'est bien ce que vous avez vécu ?"

### 4.4 Quand Utiliser

- Réponses moyennes à longues
- Vérification détaillée de compréhension
- Contexte complexe
- Questions de clarification importantes

---

## 5. Niveau 3 — Reformulation Révélatrice

### 5.1 Objectif

Révéler des tensions ou des contradictions dans la réponse du candidat, ou faire des connexions que le candidat n'a pas faites lui-même.

### 5.2 Structure

**Template :**
```
J'entends deux choses dans ce que
vous venez de dire.
D'un côté [élément 1].
De l'autre [élément 2].
Est-ce que ces deux dimensions
étaient en tension pour vous ?
```

### 5.3 Exemples

**Exemple 1 :**
- Candidat : "J'aime travailler en équipe mais je préfère prendre les décisions seul."
- Reformulation : "J'entends deux choses dans ce que vous venez de dire. D'un côté, vous aimez travailler en équipe. De l'autre, vous préférez prendre les décisions seul. Est-ce que ces deux dimensions étaient en tension pour vous ?"

**Exemple 2 :**
- Candidat : "Je cherche un poste stable mais je veux aussi de nouveaux défis."
- Reformulation : "J'entends deux choses dans ce que vous venez de dire. D'un côté, vous cherchez un poste stable. De l'autre, vous voulez aussi de nouveaux défis. Est-ce que ces deux dimensions étaient en tension pour vous ?"

**Exemple 3 :**
- Candidat : "J'ai quitté mon poste parce que je voulais plus de responsabilités, mais je ne voulais pas de pression."
- Reformulation : "J'entends deux choses dans ce que vous venez de dire. D'un côté, vous vouliez plus de responsabilités. De l'autre, vous ne vouliez pas de pression. Est-ce que ces deux dimensions étaient en tension pour vous ?"

### 5.4 Quand Utiliser

- Réponses avec contradictions ou tensions
- Réponses complexes avec plusieurs dimensions
- Exploration des zones d'ombre
- Questions de challenge ou de clarification profonde

## 6. Protocole de Sélection du Niveau

### 6.1 Critères de Sélection

**Niveau 1 — Simple :**
- Réponse courte (< 30 secondes)
- Réponse simple et claire
- Pas de contradictions apparentes
- Pas de contexte complexe

**Niveau 2 — Enrichie :**
- Réponse moyenne (30-60 secondes)
- Réponse avec contexte détaillé
- Contexte complexe mais cohérent
- Besoin de vérification détaillée

**Niveau 3 — Révélatrice :**
- Réponse longue (> 60 secondes)
- Réponse avec contradictions ou tensions
- Réponse avec plusieurs dimensions
- Besoin d'exploration des zones d'ombre

### 6.2 Algorithme de Sélection

**Étape 1 — Analyser la réponse :**
- Durée de la réponse
- Complexité du contenu
- Présence de contradictions
- Présence de tensions

**Étape 2 — Sélectionner le niveau :**
- Si réponse courte et simple → Niveau 1
- Si réponse moyenne avec contexte → Niveau 2
- Si réponse longue avec contradictions → Niveau 3

**Étape 3 — Générer la reformulation :**
- Utiliser le template du niveau sélectionné
- Adapter au contenu de la réponse
- Inclure les éléments clés identifiés

**Étape 4 — Valider la reformulation ;**
- Vérifier la cohérence
- Vérifier la pertinence
- Ajuster si nécessaire

**Niveau 1 :**

**Niveau 3 :**
- "Je note deux éléments : [élément 1] et [élément 2]. Comment ces deux dimensions s'articulent-elles ?"

**Niveau 1 :**
- "Ok, donc tu as [résumé]. C'est ça ?"

**Niveau 2 :**
- "Donc, situation : [contexte], action : [action], résultat : [résultat]. C'est bien ça ?"

**Niveau 3 :**
- "J'entends deux trucs là : [élément 1] et [élément 2]. Comment ça s'articule pour toi ?"

- "Pour confirmer, vous avez [résumé]. Est-ce exact ?"

- "Contexte : [contexte], action : [action], résultat : [résultat]. Confirmez-vous ?"

**Niveau 3 :**

**Ton :** Précis et factuel

## 8. Structure de Données (TypeScript)

```typescript
interface ReformulationModel {
  reformulationId: string;
  level: 'simple' | 'enriched' | 'revealing';
  
  template: string;
  description: string;
  
  examples: {
    candidateResponse: string;
    reformulation: string;
  }[];
  
  selectionCriteria: {
    responseLength: 'short' | 'medium' | 'long';
    complexity: 'simple' | 'complex';
    contradictions: boolean;
    tensions: boolean;
  };
  
  personaAdaptation: {
    seniorBenevolent: {
      template: string;
      tone: string;
    };
    executive: {
      template: string;
      tone: string;
    };
    startup: {
      template: string;
      tone: string;
    };
    technical: {
      template: string;
      tone: string;
    };
  };
  
  whenToUse: string[];
  
  metadata: {
    version: string;
    createdAt: Date;
    lastUpdated: Date;
  };
}

interface ReformulationLibrary {
  libraryId: string;
  
  levels: {
    simple: ReformulationModel;
    enriched: ReformulationModel;
    revealing: ReformulationModel;
  };
  
  selectionProtocol: {
    step1: {
      analyze: string[];
    };
    step2: {
      select: string[];
    };
    step3: {
      generate: string[];
    };
    step4: {
      validate: string[];
    };
  };
  
  metadata: {
    version: string;
    createdAt: Date;
    lastUpdated: Date;
  };
}
```

## 9. Stockage et Gestion

### 9.1 Schéma SQL

```sql
CREATE TABLE reformulation_model (
  id VARCHAR(36) PRIMARY KEY,
  level VARCHAR(20) NOT NULL,
  
  template TEXT NOT NULL,
  description TEXT NOT NULL,
  
  examples JSON NOT NULL,
  selection_criteria JSON NOT NULL,
  persona_adaptation JSON NOT NULL,
  when_to_use JSON NOT NULL,
  
  metadata JSON NOT NULL,
  
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
);

CREATE INDEX idx_reformulation_model_level ON reformulation_model(level);

CREATE TABLE reformulation_library (
  id VARCHAR(36) PRIMARY KEY,
  
  levels JSON NOT NULL,
  selection_protocol JSON NOT NULL,
  metadata JSON NOT NULL,
  
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
);
```

## 12. Conclusion

Le modèle de reformulation structure les 3 niveaux de reformulation que le moteur utilise avant de poser la question suivante pour montrer que chaque mot a été entendu. Le niveau 1 est simple, le niveau 2 est enrichi, et le niveau 3 est révélatrice. Le protocole de sélection adapte le niveau à la complexité de la réponse.

**Points clés :**
- 3 niveaux de reformulation (simple, enrichie, révélatrice)
- Niveau 1 : vérification de compréhension de base
- Niveau 2 : vérification détaillée avec contexte, action, résultat
- Niveau 3 : révélation de tensions ou contradictions
- Protocole de sélection du niveau adaptatif
- Adaptation par persona (4 personas)
- Structure de données TypeScript
- Stockage et gestion SQL
- API endpoints pour la gestion
- Métriques d'utilisation et de qualité
