## 1. Objectif

Définir le protocole de validation du scoring par DRH humain pour le Correctif 7 Scoring Calibration. Ce document structure le processus de validation du moteur de scoring en utilisant 50 cas de calibration évalués par des DRH seniors humains.

---

## 2. Principe Fondateur

La validation du moteur de scoring par des DRH humains garantit que les scores produits par le moteur sont cohérents avec l'expertise humaine. Le protocole utilise 50 cas de calibration couvrant divers types de postes et profils pour calibrer le moteur et identifier les écarts.

---

## 3. Processus de Validation

### 3.1 Sélection des Cas de Calibration

**Critères de sélection :**
- Diversité des types de postes (DRH, Manager RH, Commercial, Technique, Management)
- Diversité des niveaux d'expérience (junior, intermédiaire, senior)
- Diversité des profils (courants, rares)
- Diversité des contextes (PME, grande entreprise, startup)

**Nombre de cas :**
- 50 cas de calibration au total
- 10 cas par type de poste principal (DRH, Manager RH, Commercial, Technique, Management)
- 5 cas junior, 3 cas intermédiaire, 2 cas senior par type de poste

### 3.2 Évaluation par DRH Humain

**Processus :**
1. Le DRH humain évalue chaque candidat sur les 6 dimensions
2. Le DRH humain attribue un score global (0-100)
3. Le DRH humain justifie son score avec des preuves
4. Le DRH humain identifie les lacunes critiques
5. Le DRH humain note les absences notables
6. Le DRH humain évalue la cohérence du candidat

**Format d'évaluation :**
```
Candidat : [Nom]
Poste : [Titre]

Scores par dimension :
- Compétences techniques : X/5
- Expérience pertinente : X/5
- Connaissances légales : X/5
- Soft skills : X/5
- Adéquation culturelle : X/5
- Maturité : X/5

Score global : X/100

Justification :
→ Preuve 1 : [citation exacte ou fait]
→ Preuve 2 : [citation exacte ou fait]

Lacunes critiques : [liste]

Absences notables : [liste avec pénalités]

Cohérence : [élevée / standard / faible]
```

### 3.3 Comparaison Moteur / DRH Humain

**Processus :**
1. Le moteur évalue le même candidat avec la nouvelle grille de scoring
2. Le moteur calcule le score final selon la formule de calibration
3. Comparaison des scores moteur vs DRH humain
4. Calcul de l'écart (score moteur − score DRH)
5. Analyse des causes des écarts

**Seuil d'acceptabilité :**
- Écart ≤ 5 points : Acceptable
- Écart 6-10 points : À analyser
- Écart > 10 points : À corriger

### 3.4 Analyse des Écarts

**Causes possibles des écarts :**
- Mauvaise application du Principe 1 (aucun point sans preuve)
- Mauvaise identification des lacunes critiques
- Mauvaise application des pénalités de silence
- Mauvaise évaluation de la cohérence
- Pondération inadaptée des dimensions
- Échelle de scoring mal calibrée

**Actions correctives :**
- Ajustement des coefficients
- Modification des critères de scoring
- Amélioration de la détection des lacunes critiques
- Raffinement de l'évaluation de la cohérence
- Mise à jour des benchmarks

## 5. Protocole de Calibration

### 5.1 Phase 1 — Calibration Initiale

**Objectif :**
Calibrer le moteur sur les 50 cas initiaux.

**Processus :**
1. Évaluation des 50 cas par 3 DRH seniors humains
2. Calcul du score moyen DRH pour chaque cas
3. Évaluation des 50 cas par le moteur
4. Comparaison des scores moteur vs score moyen DRH
5. Calcul de l'écart moyen
6. Analyse des écarts > 10 points
7. Ajustement du moteur
8. Réévaluation des cas avec écarts > 10 points
9. Itération jusqu'à écart moyen ≤ 5 points

**Critère de succès :**
- Écart moyen ≤ 5 points
- Écart maximum ≤ 10 points
- Taux de cas avec écart ≤ 5 points ≥ 80%

### 5.2 Phase 2 — Validation Croisée

**Objectif :**
Valider la calibration avec des DRH différents.

**Processus :**
1. Sélection de 20 cas représentatifs
2. Évaluation par 5 DRH seniors différents de la phase 1
3. Comparaison des scores DRH vs moteur
4. Calcul de l'écart moyen
5. Analyse des écarts > 10 points
6. Ajustement si nécessaire

**Critère de succès :**
- Écart moyen ≤ 5 points
- Écart maximum ≤ 10 points
- Taux de cas avec écart ≤ 5 points ≥ 80%

### 5.3 Phase 3 — Calibration Continue

**Objectif :**
Maintenir la calibration dans le temps.

**Processus :**
1. Ajout mensuel de 5 nouveaux cas
2. Évaluation par DRH humain
3. Comparaison avec le moteur
4. Ajustement si écart > 10 points
5. Mise à jour des benchmarks si nécessaire

**Fréquence :**
- Mensuelle
- 5 nouveaux cas par mois

## 7. Stockage et Gestion

### 7.1 Schéma SQL

```sql
CREATE TABLE calibration_case (
  id VARCHAR(36) PRIMARY KEY,
  candidate_id VARCHAR(36) NOT NULL,
  position_id VARCHAR(36) NOT NULL,
  
  case_type JSON NOT NULL,
  human_evaluation JSON NOT NULL,
  engine_evaluation JSON NOT NULL,
  comparison JSON NOT NULL,
  metadata JSON NOT NULL,
  
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
);

CREATE INDEX idx_calibration_case_candidate ON calibration_case(candidate_id);
CREATE INDEX idx_calibration_case_position ON calibration_case(position_id);

CREATE TABLE calibration_protocol (
  id VARCHAR(36) PRIMARY KEY,
  
  phase1 JSON NOT NULL,
  phase2 JSON NOT NULL,
  phase3 JSON NOT NULL,
  case_distribution JSON NOT NULL,
  metadata JSON NOT NULL,
  
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
);
```

## 10. Conclusion

Le protocole de validation du scoring par DRH humain structure le processus de calibration du moteur en utilisant 50 cas de calibration. Processus en 3 phases : Phase 1 — Calibration initiale (50 cas évalués par 3 DRH seniors, itération jusqu'à écart moyen ≤ 5 points), Phase 2 — Validation croisée (20 cas évalués par 5 DRH différents, validation de la calibration), Phase 3 — Calibration continue (5 nouveaux cas par mois, ajustement si nécessaire). Répartition des 50 cas : 20 cas RH (DRH 10, Manager RH 5, Responsable Paie 5), 10 cas Commerciaux (Commercial 5, Account Manager 5), 10 cas Techniques (Ingénieur 5, Développeur 5), 10 cas Management (Manager 5, Team Lead 5). Comparaison moteur vs DRH humain avec seuil d'acceptabilité : écart ≤ 5 points (acceptable), 6-10 points (à analyser), > 10 points (à corriger). Structure de données TypeScript, stockage SQL, API endpoints pour la gestion.
