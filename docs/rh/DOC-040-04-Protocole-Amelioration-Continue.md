# DOC-040-04 : Protocole d'Amélioration Continue Basé sur les Feedbacks Candidats

**Version:** 1.0  
**Date:** 2026-08-03  
**Statut:** Draft  
**Auteur:** Trajectoire Team

---

## 1. Objectif

Définir le protocole d'amélioration continue basé sur les feedbacks candidats pour MVP-040 Candidate Feedback Loop. Ce document structure le cycle d'amélioration continue, les actions correctives par type de problème, les priorités, le suivi de l'efficacité, et l'intégration avec les autres MVPs.

---

## 2. Principe Fondateur

Le moteur apprend des candidats. Les feedbacks candidats sont une donnée précieuse pour améliorer continuellement l'expérience candidat. Le protocole d'amélioration continue transforme les feedbacks en actions concrètes, mesure l'efficacité de ces actions, et ajuste le système en conséquence. C'est un cycle sans fin d'amélioration.

---

## 3. Cycle d'Amélioration Continue

### 3.1 Étape 1 — Collecte des Feedbacks

**Actions :**
- Envoyer le questionnaire dans les 5 minutes après l'entretien
- Collecter les réponses
- Stocker les feedbacks dans la base de données

**Fréquence :**
- Continue
- Après chaque entretien

**Responsable :**
- Système automatique

### 3.2 Étape 2 — Analyse des Feedbacks

**Actions :**
- Analyser chaque feedback automatiquement
- Classifier les feedbacks (Excellent, Bon, Satisfaisant, À améliorer, Insuffisant)
- Identifier les alertes (score < 3 sur une question)
- Identifier les tendances

**Fréquence :**
- En temps réel
- Rapport quotidien
- Rapport hebdomadaire
- Rapport mensuel

**Responsable :**
- Système automatique

### 3.3 Étape 3 — Identification des Problèmes

**Actions :**
- Identifier les problèmes récurrents
- Classifier les problèmes par type
- Prioriser les problèmes
- Assigner les problèmes aux MVPs concernés

**Fréquence :**
- Quotidienne
- Hebdomadaire
- Mensuelle

**Responsable :**
- Équipe produit
- Équipe technique

### 3.4 Étape 4 — Planification des Actions

**Actions :**
- Définir les actions correctives
- Prioriser les actions
- Assigner les responsables
- Définir les échéances

**Fréquence :**
- Hebdomadaire
- Mensuelle

**Responsable :**
- DRH
- Équipe produit
- Équipe technique

### 3.5 Étape 5 — Mise en Œuvre des Actions

**Actions :**
- Mettre en œuvre les actions correctives
- Former les recruteurs si nécessaire
- Ajuster les paramètres du moteur
- Tester les changements

**Fréquence :**
- Continue
- Selon les priorités

**Responsable :**
- Équipe technique
- Équipe produit
- DRH

### 3.6 Étape 6 — Mesure de l'Efficacité

**Actions :**
- Mesurer l'impact des actions
- Comparer les feedbacks avant et après
- Analyser les tendances
- Ajuster les actions si nécessaire

**Fréquence :**
- Hebdomadaire
- Mensuelle

**Responsable :**
- Équipe produit
- Équipe technique

### 3.7 Étape 7 — Ajustement

**Actions :**
- Ajuster les actions si inefficaces
- Documenter les bonnes pratiques
- Mettre à jour les protocoles
- Communiquer les résultats

**Fréquence :**
- Mensuelle
- Trimestrielle

**Responsable :**
- DRH
- Équipe produit
- Équipe technique

## 4. Actions Correctives par Type de Problème

### 4.1 Problème d'Écoute (Question 1 < 3)

**MVP concerné :**
MVP-036 Active Listening Engine

**Actions immédiates :**
- Analyser l'entretien pour identifier les moments d'écoute insuffisante
- Former le recruteur sur l'écoute active
- Ajuster la bibliothèque de signaux d'écoute

**Actions à moyen terme :**
- Augmenter la fréquence des signaux d'écoute
- Ajuster les paramètres du moteur
- Créer des formations sur l'écoute active

**Actions à long terme :**
- Intégrer l'écoute active dans la culture de l'entreprise
- Documenter les bonnes pratiques
- Partager les apprentissages

**KPIs :**
- Score moyen sur écoute
- Taux de feedbacks avec score < 3 sur écoute
- Temps de mise en œuvre

### 4.2 Problème de Pertinence (Question 2 < 3)

**MVP concerné :**
Bibliothèque de Questions

**Actions immédiates :**
- Identifier les questions mal perçues
- Analyser les commentaires libres pour comprendre pourquoi
- Ajuster ou remplacer les questions problématiques

**Actions à moyen terme :**
- Améliorer la formulation des questions
- Adapter les questions au contexte du poste
- Former les recruteurs sur la formulation des questions

**Actions à long terme :**
- Créer une bibliothèque de questions par type de poste
- Documenter les bonnes pratiques
- Partager les apprentissages

**KPIs :**
- Score moyen sur pertinence
- Taux de feedbacks avec score < 3 sur pertinence
- Nombre de questions ajustées

### 4.3 Problème d'Authenticité (Question 3 < 3)

**MVPs concernés :**
MVP-038 Stress Management Engine
MVP-039 Benevolent Unmasking Engine

**Actions immédiates :**
- Analyser le niveau de stress détecté
- Analyser le niveau de masque détecté
- Vérifier si les protocoles ont été appliqués

**Actions à moyen terme :**
- Ajuster les protocoles de désescalade (MVP-038)
- Ajuster les techniques de démasquage (MVP-039)
- Former les recruteurs sur la gestion du stress et le démasquage

**Actions à long terme :**
- Intégrer la gestion du stress dans la culture de l'entreprise
- Intégrer le démasquage bienveillant dans la culture de l'entreprise
- Documenter les bonnes pratiques
- Partager les apprentissages

**KPIs :**
- Score moyen sur authenticité
- Taux de feedbacks avec score < 3 sur authenticité
- Taux d'application des protocoles

### 4.4 Problème de NPS (NPS < 0)

**MVPs concernés :**
Tous les MVPs

**Actions immédiates :**
- Analyse approfondie de tous les feedbacks
- Réunion d'urgence avec l'équipe
- Plan d'action immédiat

**Actions à moyen terme :**
- Révision complète du processus
- Ajustements majeurs des MVPs
- Formation intensive des recruteurs

**Actions à long terme :**
- Restructuration du processus si nécessaire
- Changement de culture si nécessaire
- Communication transparente

**KPIs :**
- NPS
- Tendance NPS
- Temps de récupération

## 5. Priorisation des Actions

### 5.1 Critères de Priorité

**Critère 1 — Impact :**
- Impact élevé sur l'expérience candidat
- Impact élevé sur le NPS
- Impact élevé sur la réputation

**Critère 2 — Fréquence :**
- Problème fréquent
- Problème récurrent
- Problème affectant de nombreux candidats

**Critère 3 — Gravité :**
- Problème critique (NPS < 0)
- Problème majeur (score < 2)
- Problème mineur (score 2-3)

**Critère 4 — Facilité de mise en œuvre :**
- Facile à mettre en œuvre
- Moyennement difficile
- Difficile à mettre en œuvre

### 5.2 Matrice de Priorité

**Priorité 1 — Critique :**
- Impact élevé + Fréquence élevée + Gravité élevée
- Action immédiate
- Ressources maximales

**Priorité 2 — Haute :**
- Impact élevé + Fréquence élevée
- Action dans la semaine
- Ressources élevées

**Priorité 3 — Moyenne :**
- Impact moyen + Fréquence moyenne
- Action dans le mois
- Ressources moyennes

**Priorité 4 — Basse :**
- Impact faible + Fréquence faible
- Action dans le trimestre
- Ressources faibles

## 6. Suivi de l'Efficacité

### 6.1 Mesure de l'Efficacité

**Méthode :**
- Comparer les feedbacks avant et après l'action
- Mesurer l'évolution du score moyen
- Mesurer l'évolution du NPS
- Analyser les tendances

**Période :**
- Court terme : 7 jours
- Moyen terme : 30 jours
- Long terme : 90 jours

**KPIs :**
- Amélioration du score moyen
- Amélioration du NPS
- Réduction du taux de feedbacks avec score < 3
- Satisfaction des recruteurs

### 6.2 Ajustement

**Si l'action est efficace :**
- Documenter la bonne pratique
- Étendre la pratique à d'autres contextes
- Partager l'apprentissage

**Si l'action est partiellement efficace :**
- Ajuster l'action
- Tester l'ajustement
- Mesurer à nouveau

**Si l'action est inefficace :**
- Analyser pourquoi
- Essayer une approche différente
- Consulter les experts

## 10. Stockage et Gestion

### 10.1 Schéma SQL

```sql
CREATE TABLE improvement_action (
  id VARCHAR(36) PRIMARY KEY,
  
  problem_type VARCHAR(20) NOT NULL,
  mvp_concerned VARCHAR(50) NOT NULL,
  
  priority VARCHAR(20) NOT NULL,
  
  description TEXT NOT NULL,

  metadata JSON NOT NULL,
  
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
);

CREATE INDEX idx_improvement_action_problem_type ON improvement_action(problem_type);
CREATE INDEX idx_improvement_action_mvp ON improvement_action(mvp_concerned);
CREATE INDEX idx_improvement_action_priority ON improvement_action(priority);
CREATE INDEX idx_improvement_action_status ON improvement_action(status);

CREATE TABLE continuous_improvement_protocol (
  id VARCHAR(36) PRIMARY KEY,
```

## 12. Indicateurs de Suivi

### 12.1 Métriques d'Amélioration

| Métrique | Description | Cible |
|----------|-------------|-------|
| Taux de mise en œuvre | Actions mises en œuvre / actions planifiées | ≥ 90% |
- Efficacité moyenne | Amélioration moyenne après action | ≥ 0.5 |
- Temps de mise en œuvre | Temps moyen avant mise en œuvre | ≤ 7 jours |

| Métrique | Description | Cible |

## 13. Conclusion

Le protocole d'amélioration continue basé sur les feedbacks candidats structure le cycle d'amélioration continue en 7 étapes (collecte, analyse, identification, planification, mise en œuvre, mesure, ajustement). Les actions correctives sont définies par type de problème (écoute, pertinence, authenticité, NPS) et priorisées selon l'impact, la fréquence, la gravité, et la facilité de mise en œuvre. L'efficacité des actions est mesurée et les actions sont ajustées si nécessaire. L'intégration avec les autres MVPs assure une amélioration coordonnée de l'ensemble du système.

**Points clés :**
- Cycle d'amélioration continue en 7 étapes
- Actions correctives par type de problème (écoute → MVP-036, pertinence → Bibliothèque, authenticité → MVP-038 + MVP-039, NPS → Tous)
- Priorisation selon impact, fréquence, gravité, facilité
- Matrice de priorité (Critique, Haute, Moyenne, Basse)
- Mesure de l'efficacité (court terme 7 jours, moyen terme 30 jours, long terme 90 jours)
- Ajustement selon l'efficacité
- Intégration avec les autres MVPs
- Communication interne et externe
- Structure de données TypeScript
- Stockage et gestion SQL
- API endpoints pour la gestion
- Métriques d'amélioration et d'impact
