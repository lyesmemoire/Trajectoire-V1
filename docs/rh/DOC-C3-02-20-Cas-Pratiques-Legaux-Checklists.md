**Version:** 1.0  
**Date:** 2026-08-04

**Auteur:** Trajectoire Team

---

## 1. Objectif

Définir 20 cas pratiques légaux standards avec leurs checklists d'éléments obligatoires à mentionner pour le Correctif 3 Legal Knowledge Validation. Ce document structure les cas par domaine légal, avec les éléments obligatoires, leur criticité, et les questions de creusage ciblées.

---

## 2. Principe Fondateur

Chaque cas pratique légal standard est accompagné d'une checklist d'éléments obligatoires à mentionner. Pendant que le candidat répond, le moteur coche mentalement les éléments cités. Après la réponse, le moteur détecte les lacunes et applique un creusage ciblé sur les éléments critiques manquants.

## 3. Domaine 1 — Contrats et Relations Individuelles

### 3.1 Cas Type 1 — Licenciement Salarié Protégé

**Description du cas :**
"Un délégué du personnel a commis une faute grave. Comment procédez-vous à son licenciement ?"

**Checklist des éléments obligatoires à mentionner :**
- ✓ Convocation entretien préalable (critique)
- ✓ Réunion d'information du CSE (critique)
- ✓ Demande d'autorisation à l'Inspecteur du Travail (CRITIQUE - OBLIGATOIRE)
- ✓ Délai de réponse de l'Inspection (significatif)
- ✓ Recours possibles du salarié (significatif)
- ✓ Conséquences du refus d'autorisation (significatif)

**Question de creusage si autorisation Inspection du Travail non mentionnée :**
"Quelle est la procédure spécifique pour licencier un salarié protégé par rapport à un salarié ordinaire ?"

**Si toujours absent :**
- Score légal : 1/5
- Note : "Lacune critique. Méconnaissance de la procédure de licenciement protégé. Risque juridique majeur pour ce poste."

### 3.2 Cas Type 2 — Rupture Conventionnelle

**Description du cas :**
"Un salarié souhaite partir à l'amiable. Comment gérez-vous une rupture conventionnelle ?"

**Checklist des éléments obligatoires à mentionner :**
- ✓ Entretien préalable (critique)
- ✓ Signature de la convention (critique)
- ✓ Délai de rétractation (15 jours) (critique)
- ✓ Demande d'homologation à la DREETS (critique)
- ✓ Indemnité de rupture conventionnelle (significatif)
- ✓ Possibilité de refus d'homologation (significatif)

**Question de creusage si homologation DREETS non mentionnée :**
"Quelle est la procédure administrative après la signature de la convention de rupture ?"

### 3.3 Cas Type 3 — Modification Substantielle du Contrat

**Description du cas :**
"L'entreprise souhaite modifier le lieu de travail d'un salarié de Paris à Lyon. Comment procédez-vous ?"

**Checklist des éléments obligatoires à mentionner :**
- ✓ Distinction modification substantielle / non substantielle (critique)
- ✓ Accord obligatoire du salarié pour modification substantielle (CRITIQUE)
- ✓ Délai de réflexion (1 mois) (critique)
- ✓ Refus du salarié = licenciement possible (significatif)
- ✓ Information suffisante pour modification non substantielle (significatif)

**Question de creusage si accord salarié non mentionné :**
"Le salarié peut-il refuser cette modification ? Quelles sont les conséquences de son refus ?"

### 3.4 Cas Type 4 — Inaptitude Médicale

**Description du cas :**
"Le médecin du travail déclare un salarié inapte à son poste. Comment gérez-vous cette situation ?"

**Checklist des éléments obligatoires à mentionner :**
- ✓ Visite de reprise obligatoire (critique)
- ✓ Avis d'inaptitude (critique)
- ✓ Reclassement obligatoire (CRITIQUE)
- ✓ Recherche de postes adaptés (critique)
- ✓ Licenciement si reclassement impossible (significatif)
- ✓ Procédure spécifique (significatif)

**Question de creusage si reclassement non mentionné :**
"Quelle est votre obligation légale suite à l'avis d'inaptitude ?"

## 9. Stockage et Gestion

### 9.1 Schéma SQL

```sql
CREATE TABLE legal_case_study (
  id VARCHAR(36) PRIMARY KEY,
  
  domain VARCHAR(50) NOT NULL,
  case_type VARCHAR(50) NOT NULL,
  
  description TEXT NOT NULL,
  checklist JSON NOT NULL,
  drilling_question JSON NOT NULL,
  scoring JSON NOT NULL,
  metadata JSON NOT NULL,
  
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
);

CREATE INDEX idx_legal_case_domain ON legal_case_study(domain);
CREATE INDEX idx_legal_case_type ON legal_case_study(case_type);

CREATE TABLE legal_case_study_library (
  id VARCHAR(36) PRIMARY KEY,
  
  domain1 JSON NOT NULL,
  domain2 JSON NOT NULL,
  domain3 JSON NOT NULL,
  domain4 JSON NOT NULL,
  domain5 JSON NOT NULL,
  metadata JSON NOT NULL,
  
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
);
```

## 12. Conclusion

Les 20 cas pratiques légaux standards couvrent les 5 domaines du niveau DRH. Domaine 1 (contrats et relations individuelles) : 4 cas (licenciement salarié protégé, rupture conventionnelle, modification substantielle, inaptitude). Domaine 2 (relations collectives) : 4 cas (PSE, élection CSE, grève, négociation d'accord). Domaine 3 (temps de travail et rémunération) : 4 cas (heures supplémentaires, forfait jours, égalité salariale, participation). Domaine 4 (formation et développement) : 3 cas (CPF, plan de formation, Pro-A). Domaine 5 (santé et sécurité) : 5 cas (harcèlement, accident du travail, document unique, maladie professionnelle, obligation générale de sécurité). Chaque cas a une checklist d'éléments obligatoires avec criticité (critique, significatif, mineur). Une question de creusage est définie pour chaque élément critique. Le scoring légal varie de 5/5 (tous éléments critiques présents) à 1/5 (3 éléments critiques ou plus absents).

**Points clés :**
- 20 cas pratiques légaux standards
- Domaine 1 : 4 cas (contrats)
- Domaine 2 : 4 cas (collectif)
- Domaine 3 : 4 cas (temps et rémunération)
- Domaine 4 : 3 cas (formation)
- Domaine 5 : 5 cas (santé et sécurité)
- Checklist par cas avec criticité
- Question de creusage par élément critique
- Scoring légal : 5/5 à 1/5
- Structure de données TypeScript
- Stockage et gestion SQL
- API endpoints pour la gestion
- Métriques de couverture et d'utilisation
