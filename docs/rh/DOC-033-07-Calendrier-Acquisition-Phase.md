## 1. Objectif

Définir le calendrier d'acquisition par phase pour MVP-033 Real Data Foundation. Ce calendrier structure le timeline pour les 4 phases d'acquisition de données (historiques, temps réel, profondes, continu) avec des milestones clairs, des livrables spécifiques, et des indicateurs de suivi.

---

## 2. Principe Fondateur

L'acquisition de données est un processus progressif qui s'étale sur 12 mois minimum. Chaque phase a ses objectifs, ses livrables, et ses indicateurs de succès. Le calendrier permet de suivre la progression et d'ajuster la stratégie si nécessaire.

---

## 3. Phase 1 — Données Historiques (Mois 1-2)

### 3.1 Objectifs

**Objectif principal :**
Constituer la base initiale à partir de données existantes.

**Objectifs spécifiques :**
- Identifier et contacter 10 partenaires potentiels
- Signer 3 à 5 contrats de partage de données
- Collecter 250 entretiens anonymisés
- Collecter 100 paires CV/Poste avec décisions
- Identifier 50 patterns initiaux
- Constituer le premier golden dataset

---

### 3.2 Calendrier Détaillé

**Mois 1 :**
- Semaine 1-2 : Identification des cibles
  - Recherche de cabinets de recrutement
  - Recherche d'entreprises beta
  - Évaluation des profils
  - Score de priorité

- Semaine 3-4 : Approche initiale
  - Envoi d'emails d'approche
  - Premiers contacts téléphoniques
  - Présentations du partenariat

**Mois 2 :**
- Semaine 5-6 : Négociation
  - Discussions des termes du contrat
  - Ajustements des contreparties
  - Validation juridique

- Semaine 7-8 : Signature et onboarding
  - Signature des contrats
  - Configuration de l'accès beta
  - Premier transfert de données
  - Validation de l'anonymisation

---

### 3.3 Livrables

**Livrables fin de Phase 1 :**
- 3 à 5 contrats signés
- 250 entretiens anonymisés collectés
- 100 paires CV/Poste collectées
- 50 patterns initiaux identifiés
- Premier golden dataset constitué
- Rapport de progression Phase 1

## 8. Stockage et Gestion

### 8.1 Schéma SQL

```sql
CREATE TABLE acquisition_calendar (
  id VARCHAR(36) PRIMARY KEY,
  version VARCHAR(50) NOT NULL,
  created_at TIMESTAMP NOT NULL,
  
  phases JSON NOT NULL,
  current_phase VARCHAR(20) NOT NULL CHECK (current_phase IN ('phase1', 'phase2', 'phase3', 'phase4')),
  overall_progress JSON NOT NULL,
  metadata JSON NOT NULL,
  
  UNIQUE KEY idx_acquisition_calendar_version (version)
);

CREATE TABLE phase_milestone (
  id VARCHAR(36) PRIMARY KEY,
  calendar_id VARCHAR(36) NOT NULL,
  
  phase VARCHAR(20) NOT NULL CHECK (phase IN ('phase1', 'phase2', 'phase3', 'phase4')),
  week_number INT NOT NULL,
  period VARCHAR(50) NOT NULL,
  activities JSON NOT NULL,
  
  status VARCHAR(20) NOT NULL CHECK (status IN ('not_started', 'in_progress', 'completed', 'delayed')),
  completed_at TIMESTAMP,
  
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  
  FOREIGN KEY (calendar_id) REFERENCES acquisition_calendar(id)
);

CREATE INDEX idx_phase_milestone_calendar ON phase_milestone(calendar_id);
CREATE INDEX idx_phase_milestone_phase ON phase_milestone(phase);
CREATE INDEX idx_phase_milestone_status ON phase_milestone(status);
```

## 11. Gestion des Retards

### 11.1 Identification des Retards

**Critères de retard :**
- Milestone non complété à la date prévue
- Livrable non livré à la date prévue
- Indicateur de succès non atteint

### 11.2 Plan de Rattrapage

**Actions de rattrapage :**
- Réallocation des ressources
- Priorisation des tâches critiques
- Extension des délais (si nécessaire)
- Révision des objectifs (si nécessaire)

### 11.3 Communication

**En cas de retard :**
- Notification immédiate au Comité Data
- Explication du retard
- Plan de rattrapage proposé
- Validation du plan par le Comité Data
