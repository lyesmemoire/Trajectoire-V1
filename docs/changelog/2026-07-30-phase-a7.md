# Phase A.7 - PerceptionEngine Refactor with ObservationCatalog and ObservationResolver

**Date**: 2026-07-30  
**Objectifs**: Refactoriser PerceptionEngine pour consommer NormalizedText + EntityFacts et produire ObservationFacts

## Fichiers créés

- `apps/web/src/domain/cognitive/catalogs/ObservationCatalog.ts` - Catalogue d'observations avec types, patterns et expected fields
- `apps/web/src/lib/ai/engines/ObservationResolver.ts` - Résolveur d'observations canoniques
- `apps/web/src/lib/ai/engines/PerceptionEngine.ts` - Nouveau PerceptionEngine héritant de BaseEngine (remplace l'ancien)
- `apps/web/src/lib/ai/runtime/EngineCapability.ts` - Système de vérification des contrats entre moteurs
- `tests/phase-a7/perception-engine.test.ts` - Tests unitaires PerceptionEngine et ObservationResolver
- `tests/phase-a7/runtime-perception-integration.test.ts` - Tests d'intégration Runtime + PerceptionEngine

## Fichiers modifiés

- `apps/web/src/lib/ai/engines/FactBuilder.ts` - Extension de observation() avec observationType, expectedFields, sourceText
- `apps/web/src/lib/ai/runtime/CognitiveRuntime.ts` - Ajout de EngineCapabilityRegistry et vérification des contrats
- `apps/web/src/lib/ai/engines/perception/PerceptionEngine.ts` - Supprimé (remplacé par nouveau PerceptionEngine)

## Breaking changes

- PerceptionEngine ne consomme plus `candidateAnswer: string`, mais `normalizedText: string` + `entityFacts: any[]`
- PerceptionEngine ne produit plus de perceptions directes, mais des ObservationFacts avec catégories

## Tests ajoutés

24 tests (19 unitaires + 5 intégration) :
- PerceptionEngine unit tests : manifest validation, production observations, failure observations, responsibility observations, metric observations, claim observations, unknown observations, complex extraction, no skills/claims inference, event emission, empty text, no observations, consume EntityFacts
- ObservationResolver tests : production incident, failure, responsibility, unknown, null for unknown pattern, get by category
- Runtime integration : execute via Runtime, receive OBSERVATION_EXTRACTED event, extract with canonical types, track execution metrics, no skills/claims inference

## Couverture

Tests unitaires et d'intégration complets

## Notes

- PerceptionEngine refactorisé pour hériter de BaseEngine (cohérence avec EntityExtractionEngine)
- PerceptionEngine consomme maintenant NormalizedText + EntityFacts (plus de texte brut)
- PerceptionEngine produit uniquement ObservationFacts (pas d'inférence, pas d'évaluation)
- ObservationCatalog définit les types d'observations : ClaimObservation, ExperienceObservation, ProductionObservation, MetricObservation, ResponsibilityObservation, FailureObservation, UnknownObservation, QuestionObservation
- ObservationResolver normalise les observations (comme CanonicalEntityResolver pour entités)
- EngineCapabilityRegistry permet au Runtime de vérifier les contrats entre moteurs (produces/consumes)

- PerceptionEngine ne juge rien, ne fait pas d'inférence, extrait uniquement des observations
- Prépare le pipeline pour EvidenceEngine qui travaillera sur ObservationFacts + EntityFacts
