# Phase A.8 - EvidenceEngine with Policies, EvidenceLedger and EvidenceLinker

**Date**: 2026-07-30  
**Objectifs**: Construire un EvidenceEngine centré sur l'évaluation de preuves avec Policies, EvidenceDimensionCatalog, EvidenceLinker et EvidenceLedger

## Fichiers créés

- `apps/web/src/domain/cognitive/catalogs/EvidenceDimensionCatalog.ts` - Catalogue de dimensions piloté par données (specificity, ownership, production, quantification, failure, recency, corroboration, verifiability)
- `apps/web/src/lib/ai/engines/evidence/policies/EvidencePolicy.ts` - Interface de base pour les policies
- `apps/web/src/lib/ai/engines/evidence/policies/MinimumEvidencePolicy.ts` - Policy pour vérifier le seuil minimum de preuve
- `apps/web/src/lib/ai/engines/evidence/policies/EvidenceQualityPolicy.ts` - Policy pour évaluer la qualité des preuves
- `apps/web/src/lib/ai/engines/evidence/policies/CorroborationPolicy.ts` - Policy pour évaluer la corroboration
- `apps/web/src/lib/ai/engines/evidence/policies/WeakEvidencePolicy.ts` - Policy pour identifier les preuves faibles
- `apps/web/src/lib/ai/engines/evidence/EvidenceLedger.ts` - Registre des preuves avec métadonnées complètes (origin observation, assessment, dimensions, policies applied, timestamp, engine version, prompt version, provider, trace id)
- `apps/web/src/lib/ai/engines/evidence/EvidenceLinker.ts` - Composant déterministe pour les liens entre preuves (supports, duplicates, contradicts, extends, refines, supersedes)
- `apps/web/src/lib/ai/engines/EvidenceEngine.ts` - EvidenceEngine évaluateur de preuves avec LLM + Policies
- `tests/phase-a8/evidence-engine.test.ts` - Tests unitaires EvidenceEngine avec scénarios spécifiques
- `tests/phase-a8/runtime-evidence-integration.test.ts` - Tests d'intégration Runtime + EvidenceEngine

## Fichiers modifiés

- `apps/web/src/lib/ai/runtime/ExecutionReport.ts` - Ajout de ExecutionGraph dans ExecutionReport avec nodes (durée, événements, facts consommés/produits, erreurs, budget) et edges (produces/consumes)

## Breaking changes

- EvidenceEngine consomme maintenant ObservationFacts et EntityFacts (plus de texte brut)
- EvidenceEngine produit des événements multiples : EvidenceDetected, EvidenceStrengthCalculated, MissingEvidenceDetected, EvidenceLinked
- ExecutionReport inclut maintenant executionGraph avec nodes et edges

## Tests ajoutés

19 tests (15 unitaires + 4 intégration) :
- EvidenceEngine unit tests : manifest, Cas 1 (180 microservices → evidence forte), Cas 2 (bon en Kubernetes → evidence faible), Cas 3 (production perdue → failure evidence), Cas 4 (pense être senior → evidence faible), Cas 5 (180 vs 120 services → potential conflict), ledger recording, policies application
- EvidenceDimensionCatalog tests : dimensions disponibles, get by id
- EvidenceLinker tests : détermination déterministe, potential conflict reference, filter by type
- EvidenceLedger tests : record/retrieve, statistics
- Runtime integration : execute via Runtime, receive EVIDENCE_DETECTED event, receive EVIDENCE_STRENGTH_CALCULATED event, record in ledger via Runtime

## Notes

- EvidenceEngine évalue les preuves basées sur ObservationFacts et EntityFacts
- EvidenceDimensionCatalog définit les dimensions avec poids et policies associées
- Policies (MinimumEvidencePolicy, EvidenceQualityPolicy, CorroborationPolicy, WeakEvidencePolicy) séparent la logique métier du moteur
- EvidenceLedger conserve toutes les métadonnées pour l'explicabilité (origin observation, assessment, dimensions, policies applied, timestamp, engine version, prompt version, provider, trace id)
- EvidenceLinker est un composant déterministe pour les liens (pas de décision LLM directe sur supports/contradicts)
- EvidenceEngine émet des événements multiples pour permettre le replay sélectif
- ExecutionReport inclut maintenant un ExecutionGraph pour diagnostiquer les pipelines complexes
- Pipeline maintenant : Normalizer → EntityExtraction → Perception → Evidence → Contradiction → Temporal → Confidence
- EvidenceEngine ne fait pas d'inférence, évalue uniquement la qualité des preuves
